# Источники и происхождение данных

Общая лента получает сообщения из учебного набора и административного API ручного/JSON-импорта. Новый кабинет читает её, но не содержит старой формы загрузки источников. Автоматический RSS/Telegram/MAX-мониторинг, интеграции NMH и закрытые базы не подключены.

В `src/data/demo.ts` находятся **14 исходных сообщений, образующих 12 учебных событий**, и 3 вымышленные точки; CSV — `src/data/demo-locations.csv`. Издатели подписаны как учебные. Адреса, компании и координаты вымышлены; координаты не получены геокодированием. Маркировка «Учебные данные» относится к набору независимо от входа в настоящий локальный аккаунт.

Сообщение хранит издателя, URL при наличии, время публикации, timezone, время получения, способ получения и исходник. Версии сохраняют текст и отпечатки; повтор не становится независимым подтверждением. Дата публикации не заменяет период события. Уточнение сохраняет историю и требует повторной проверки прежних выводов; новая версия может создать новое личное уведомление.

В новости доступны исходник, цитаты и метаданные. Цитата подтверждает происхождение фразы, а не истинность утверждения. Координаты события показываются только с подтверждающими цитатами; неизвестная география не дорисовывается. Сохранение HTTP(S)-ссылки не делает источник официальным и не запускает обход страницы.

У каждой карточки есть ссылка источника. Для учебного сообщения и сообщения без внешнего URL это `/sources/:eventId`: точный сохранённый текст, издатель, публикация, получение и предыдущие версии. Учебная копия прямо названа учебной. Для настоящего сообщения с сохранённым безопасным HTTP(S)-адресом ссылка ведёт на публикацию. Неизвестные даты старых версий не заменяются датой последнего сообщения.

## Административный доступ

Общее операционное состояние `GET /api/state` и прежние изменяющие endpoints (`/api/messages`, `/api/messages/import`, `/api/events/...`, `/api/demo/...` и другие POST/PATCH) требуют `Authorization: Bearer <OPERATIONS_ADMIN_TOKEN>`. Токен задаётся только в серверной `.env`; при пустом значении этот доступ закрыт. Обычная cookie аккаунта не даёт административных прав. Не передавайте токен в публичный frontend или Git.

При браузерном вызове `Origin` должен совпадать с локальным origin приложения и заголовком Host; межсайтовый запрос отклоняется. Серверный CLI-запрос без Origin допустим при правильном Bearer-токене. Личный `/api/product` использует отдельную cookie-сессию и обязательную same-origin проверку изменений — [product-api.md](product-api.md).

## JSON-импорт

`POST /api/messages/import`:

```http
Content-Type: application/json
Authorization: Bearer <серверный OPERATIONS_ADMIN_TOKEN>
Origin: http://localhost:3000
```

```json
{
  "actor": "Администратор источников",
  "messages": [
    {
      "text": "Учебное сообщение. Москва: мероприятие запланировано на 15 ноября 2026, 19:00–21:00, Europe/Moscow. Место пока неизвестно.",
      "publisher": "Мой учебный источник",
      "url": null,
      "publishedAt": "2026-11-14T08:00:00+03:00",
      "timezone": "Europe/Moscow"
    }
  ]
}
```

До 50 сообщений в пакете; тело HTTP около 1 МБ; текст 10–20000 символов, AI-разбор — до 16000. Даты — ISO 8601 со смещением; неизвестные `publishedAt`/`timezone` — `null`. Сервер назначает происхождение `json`. Для явного обновления добавьте внутренний `eventId`; похожий заголовок не объединяет события.

Каждая строка сохраняется атомарно. Ответ содержит `results` с номером строки, `eventId`/`duplicate` либо ошибкой и число `imported`. После исправления можно повторить пакет. Импорт и разбор — разные операции: `POST /api/events/{eventId}/analyze` с `{ "actor": "Администратор источников" }` требует тех же административных заголовков.

Новый текст примера не имеет подготовленного DEMO-ответа. Для его анализа нужен настроенный LIVE; ошибки провайдера не подменяются fixture-успехом. Для показа без ключа используйте точные учебные исходники. [Настройка AI](ai.md).
