# API личного кабинета

Контракт TypeScript: `src/lib/product-types.ts`. Все успешные операции возвращают полный `ProductState`: `user`, `events`, `locations`, `notifications`, `unreadCount`, `mode`, `now`. Ошибки возвращаются с HTTP-статусом и `{ "error": { "message": "…" } }`. Ответы не кешируются.

В обычном режиме данные происходят только из `newsssss09`. Персональный анализ выбирает серверный `NEWS_AI_PROVIDER=gemini|groq`; для Gemini используются `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_BASE_URL`. API не принимает провайдера или ключ от браузера. В `ProductState` также входят `recommendations`, `sourceHealth`, `analysisHealth`, `highlightEventIds` и `notificationWindowDays`. `recommendations` — единственный источник содержательных карточек главной: `{id,eventId,type:opportunity|threat,title,action,reason,locationIds,locationNames,processes,startsAt,endsAt,sourceUrl}`. Неизвестный период остаётся `null`; рекомендации с известным истёкшим концом отфильтровываются сервером. `sourceUrl` назначается из сохранённого поста, не из ответа модели.

`sourceHealth.status`: `pending | ok | error | disabled`; объект содержит `channel`, безопасное `message`, даты попытки/успеха, числа полученных и изменённых постов. `analysisHealth.status`: `ready | pending | error | missing_config | sign_in`, а также безопасное `message` и счётчики. Пустая готовая выборка отличается от недоступности источника/модели. Гостям доступны посты, персональные рекомендации требуют аккаунта.

GET читает сохранённый результат и не вызывает модель. Одно серверное расписание получает публикации примерно раз в минуту и обрабатывает изменения. Ключ сохранённого анализа: пользователь + сообщение + хеш содержимого + хеш отрасли/описания/города/точек/процессов. Фотография и оценки не вызывают повторный анализ. Новый текст или значимое изменение профиля скрывает прежние советы до нового результата. Ошибки и ограниченные повторы хранятся отдельно; внешние ошибки не превращаются в успешные карточки.

Приватный хеш анализа также включает ревизию алгоритма `field-evidence-v2`: после исправления извлечения прежние результаты сохраняются как история, а очередь один раз считает новую ревизию. Публичные тела запросов и `ProductState` не меняются. При активном общем лимите выбранного провайдера `analysisHealth.message` содержит время автоматического повтора в МСК; готовые рекомендации остаются доступны. Ответ 429 сохраняет общий cooldown и возвращает занятую попытку публикации, поэтому ожидание квоты не исчерпывает три попытки разбора. Остальные ошибки сохраняют прежний ограниченный бюджет.

Текущий приватный cache-key имеет вид `providerScope:businessHash`: scope учитывает провайдера, модель и канонический URL API без ключей. RAM-кэши, долговечные результаты, cooldown и recovery разделены по этому scope; старая пауза Groq не блокирует Gemini. Ошибки транспорта Gemini имеют префикс `GEMINI_*`, старые `GROQ_*` проверки доказательств сохранены для совместимости. Автоматической подмены провайдера или fixture нет. Внутренний необязательный scope аккаунта/сообщений позволяет прогреть учебный набор той же очередью; HTTP endpoint для него не добавлялся.

У Gemini только в передаваемой модели JSON Schema убраны `minItems/maxItems`: их сочетание во вложенной схеме профиля давало фактический HTTP 400. Полная исходная Zod-схема проверяет все границы после ответа, включая минимум/максимум массива. Типы, обязательные ключи, запрет лишних полей и доказательства сохранены. Таймаут Gemini — до 60 секунд на запрос, lease — 5 минут; причина увеличения — наблюдавшаяся задержка/503 Google. Время Москвы передаётся с явным UTC+03:00. Сопоставление города поддерживает падежи Москвы/Санкт-Петербурга, а названий улиц — известные формы слова «улица» и женские прилагательные; это ограниченная нормализация, не геокодер и не общий морфологический анализатор.

Внутренний формат source-стадии изменён с независимых значений и списка `evidence` на `{value,quoteId}` у каждого факта. Сервер передаёт модели только метаданные и `source.fragments:[{id,text}]` — точные срезы исходного текста, до 64 по 1500 символов. Модель выбирает фрагмент; сервер разрешает ID и строит прежний публичный `evidence:[{field,quote}]`. Неизвестные ID, неподходящие фрагменты и факты без доказательства не принимаются. Цитаты не переписываются моделью и не подбираются сервером по предполагаемому значению; исходные проверки цитат, имён, адресов, координат, дат и релевантности остаются. Это проверка происхождения данных, а не независимое подтверждение истинности публикации. Потребители изменения — только `src/ai/personal.ts` и его unit-проверки; клиентский API сохранён.

Отдельные `PersonalNewsAnalysis`, `SourceHealth` и уникальный `SourceMessage(channel,channelMessageId)` добавлены миграцией `20261115020000_personal_news_pipeline`. Текст и ссылки поста, даты получения/публикации и хеш сохраняются в существующих SourceMessage/MessageVersion; правки не теряют прежний оригинал. Операционные endpoints и проверки авторизации сохранены. Описанный ниже учебный результат доступен только при явно включённом `RADAR_DEMO_MODE=true`; он не подставляется вместо канала.

Общие значения находятся в `src/lib/product-config.ts`: `EVENT_RADIUS_METERS = 1000` и список `BUSINESS_TYPES`.

| Метод и путь | JSON запроса |
| --- | --- |
| `GET /api/product` | — |
| `GET /api/product/geocode/reverse?latitude=…&longitude=…` | Нужна пользовательская сессия; ответ `{address:string,city:string|null}`, без изменения профиля |
| `POST /api/product/auth/register` | `name`, `email`, `password`; необязательно `businessName`, `businessType`, `city` |
| `POST /api/product/auth/login` | `email`, `password` |
| `POST /api/product/auth/logout` | `{}` |
| `PATCH /api/product/profile` | Любые из `name`, `photo`, `businessName`, `businessType`, `city`, `about` |
| `POST /api/product/locations` | `LocationInput`: обязательны `locationId`, `name`, `address`, `timezone` |
| `PATCH /api/product/locations/:id` | Изменяемые поля `LocationInput` |
| `DELETE /api/product/locations/:id` | `{}` |
| `PUT /api/product/feedback/:eventId` | `{ "value": 1 }`, `{ "value": -1 }` или `{ "value": null }` для отмены оценки |
| `POST /api/product/notifications/read` | `{ "eventId": "…" }` или `{}` для всех имеющихся уведомлений пользователя |

Все изменения требуют `Content-Type: application/json` и `Origin`, совпадающий с origin приложения. Межсайтовые запросы отклоняются. Браузер отправляет cookie при запросах к своему origin; API не принимает переданный клиентом `userId` как основание доступа.

## Аккаунты и сессии

Регистрация атомарно создаёт пользователя и сессию в PostgreSQL. Email нормализуется в нижний регистр; пароль — от 10 до 128 символов. Пароль хранится как scrypt-хеш с отдельной случайной солью. Случайный токен сессии передаётся в cookie `radar_session`; БД хранит только его SHA-256-хеш и срок действия 30 дней. Cookie имеет `HttpOnly`, `SameSite=Lax`, `Path=/`, а при HTTPS — `Secure`. Новый вход меняет идентификатор сессии браузера; выход отзывает текущую серверную сессию. Истёкшая сессия не даёт доступа.

Есть ограничение попыток входа и регистрации на email в памяти процесса. Оно не заменяет распределённую защиту от перебора, ограничения по IP и мониторинг публичного сервиса. Email не подтверждается; восстановление пароля, социальный вход и управление всеми сессиями пока не подключены. Имя аккаунта не означает проверенную личность.

## Личные данные

Без входа доступны новости и три явно учебные точки. После регистрации список точек пуст: общие демоточки не копируются и не становятся собственностью аккаунта. `UserLocation` хранится отдельно от общего `Location`. Обновление и удаление точки проверяют её `userId`; чужой идентификатор даёт 404. Одинаковый `locationId` допустим у разных владельцев.

`businessType` принимает пустую строку либо ровно одну из шести сфер: `Кофейня`, `Пекарня`, `Ресторан`, `Магазин`, `Услуги`, `Другое`. Произвольные новые значения сервер отклоняет. Старое свободное значение при чтении отображается как `Другое`; пустое остаётся незаполненным. Сфера бизнеса не подменяет явно заданные процессы точки.

Радиус мероприятий общий для всех точек: **1000 м**. Сервер принудительно применяет его при сохранении, чтении старых профилей и оценке влияния, включая гостевые демоточки. `eventRadiusMeters` сохранён в совместимом формате данных, но индивидуальное значение клиента не управляет радиусом.

Процессы точки сохраняются вместе с `LocationInput`: `openingHours`, `deliveryWindows`, `deliveryRouteStreets`, `waterDependency`. Часы и окна — массивы `{ days: number[], start: "HH:mm", end: "HH:mm" }`, дни от 1 (понедельник) до 7, время в `timezone` точки; поддерживается переход через полночь. Пустой массив означает неизвестные условия. `waterDependency`: `essential`, `optional` или `unknown`. PATCH сохраняет непереданные поля и проверяет владельца так же, как остальные изменения точки.

Фото — `null` либо data URL с PNG, JPEG или WebP. Сервер проверяет MIME, корректность base64, сигнатуру файла и размер декодированного изображения не более 500 КиБ. SVG и произвольные внешние URL не принимаются. Изображение хранится в профиле; отдельное облачное хранилище не используется.

## Новости, порядок и уведомления

Новости берутся из существующей общей модели событий. В ответе есть точный сохранённый текст источника, его издатель, дата публикации и время получения, найденные в тексте цитаты. Координаты карты и оценки влияния используются только при наличии обеих координат и соответствующих цитат с числовыми значениями. Адреса не геокодируются автоматически.

`sourceHref` всегда задаёт ссылку: сохранённый допустимый внешний HTTP(S)-URL либо `/sources/:eventId`. Учебные источники, сообщения без URL и недопустимые URL ведут к локальной сохранённой копии. `sourceUrl` оставлен для совместимости; внешняя ссылка с логином/паролем не выдаётся. Локальная страница показывает последний сохранённый источник события и честно обозначает учебное происхождение, не придумывая внешнего издателя.

`sourceVersions` содержит версии этого источника от новой к старой: `version`, точный `text`, `savedAt`, `publisher`, `publishedAt`. Если у старой версии не сохранились дата публикации или издатель, возвращаются `null` и явная подпись об отсутствии сведений. Текущие метаданные не переносятся на старую версию. Произвольная служебная metadata в ответ не попадает.

`impactKind`, `impactExplanation` и `affectedLocationNames` описывают влияние на точки:

| Значение | Условия |
| --- | --- |
| `opportunity` | Мероприятие имеет совпадение `relevant`: известные город и координаты, расстояние не больше 1000 м, пересечение с часами работы и остальные обязательные условия |
| `risk` | Перекрытие совпадает с улицей маршрута и окном доставки либо отключение воды совпадает с точным адресом/корпусом, часами работы и известной зависимостью от воды (`essential`/`optional`) |
| `neutral` | Нет точек или разбора, условия неизвестны/не совпадают, категория не поддерживается, событие отменено либо уже закончилось |

Объяснение называет совпавшие точки, время в их часовом поясе и конкретный процесс. Возможный спрос, задержка поставки или ограничение водозависимых операций обозначаются гипотезой. Нейтральная оценка не гарантирует отсутствие риска. `affectedLocationNames` содержит только установленные совпадения, а не точки с неизвестными условиями.

Для авторизованного аккаунта существующие правила `evaluate` проверяют только его точки. Лайк поднимает новость, дизлайк опускает её; оценки также немного меняют порядок других новостей той же категории. Оценки другого аккаунта не участвуют. Эта сортировка — прозрачные правила, не обученная рекомендательная нейросеть. Отсутствие точки предлагает её добавить; неизвестные условия не объявляются безопасными.

Уведомления сохраняются отдельно для каждого пользователя и каждой версии события. Повторное чтение страницы не сбрасывает `readAt`. Новая версия создаёт новое непрочитанное уведомление; прежняя запись сохраняется. Без личных точек доступны общие уведомления о новостях; при наличии точек новые уведомления создаются для совпадений и случаев, требующих проверки. На ответ формируется до 30 новых уведомлений и возвращается до 100 последних; `unreadCount` учитывает все непрочитанные. Это уведомления внутри кабинета, без email, push, MAX или Telegram.

Режим AI наследуется от сервера. Новая регистрация не подключает LIVE, ключи, внешние источники или автоматический мониторинг. DEMO остаётся подготовленной демонстрацией.

## Проверки

`tests/integration/product.test.ts` проверяет авторизацию и CSRF, изоляцию аккаунтов, фото, фиксированные сферы и радиус, сохранение процессов, ранжирование, прочитанность, происхождение координат и версии источников. Запускать через `npm run test:integration` с отдельной `TEST_DATABASE_URL`, имя БД которой оканчивается на `_test`. `tests/unit/product-impact.test.ts` проверяет условия риска/возможности и нейтральные пограничные случаи без БД. Фактические результаты прогонов — в [progress.md](progress.md).
