# Учебный бизнес и настоящий анализ Gemini

Это отдельный учебный аккаунт **«Три чашки»** с тремя вымышленными точками. Публикации для показа действительно сохранены из `@newsssss09`, но описанные в них события и адреса вымышлены; это прямо написано в самих постах. Ответы Gemini не подставляются из fixture и могут отличаться от ожиданий проверяющего.

## Подготовка и вход

Нужны Node.js 24, работающая PostgreSQL и запущенный проект по [README](../../README.md). В локальной серверной `.env` выбирается `NEWS_AI_PROVIDER=gemini`, задаётся `GEMINI_API_KEY`; модель и адрес провайдера задаются `GEMINI_MODEL` и `GEMINI_BASE_URL` по `.env.example`. `RADAR_DEMO_MODE=false`; для автоматической обработки `RADAR_SYNC_ENABLED` не должен быть `false`. После изменения настройки требуется перезапуск сервера. Ключ в этот документ и браузер не передаётся.

Подготовитель использует существующие серверные функции и не публикует новости:

```powershell
node --import tsx scripts/setup-showcase.mjs
node --import tsx scripts/setup-showcase.mjs --apply --analyze
```

Первая команда только читает и показывает план. Вторая создаёт отдельный аккаунт и сохраняет его профиль/точки через существующие серверные функции `register`, `updateProfile`, `savePersonalLocation`. Повторный запуск пропускает совпадающие данные; перед изменением уже созданного учебного аккаунта проверяет локальное подтверждение владения. Другие аккаунты и публикации не меняются. Флаг --analyze запускает настоящую очередь анализа; без него команда только сохраняет профиль и точки.

Подготовка этого аккаунта уже выполнена интегратором: **три точки сохранены**. Для входа откройте `/login` на работающем экземпляре и используйте email `anna@threecups.example`. Случайный пароль хранится **только в локальном игнорируемом `.local/showcase-credentials.json`**. Этот файл не входит в Git; пароль здесь не приводится.

## Порядок просмотра

1. Войти в отдельный учебный аккаунт и открыть `/profile`: проверить три точки и условия работы.
2. Дождаться фоновой обработки сервером. Открытие страницы и её GET-обновление сами не запускают Gemini.
3. Открыть `/`: здесь показываются только сохранённые рекомендации серверного анализа. До его завершения допустимо ожидание; ошибка провайдера должна оставаться ошибкой, без подготовленного ответа вместо неё.
4. В `/notifications` открыть нужную новость, проверить источник, период и затронутые точки. При недостаточных условиях должно быть уточнение, а не выдуманная рекомендация.

Ожидания для человека ниже **не являются фактическим ответом Gemini** и не передаются модели:

- Фестиваль в Москве: возможная возможность для «Парка» при подтверждённых координатах и пересечении времени; проверить запас/готовность смены без обещания выручки.
- Перекрытие: возможная угроза доставке «Парка» 16:00–17:00; не объявлять пешеходный доступ закрытым.
- Вода: возможная угроза работе «Офисов» по точному дому и корпусу, при подтверждённом периоде.
- Санкт-Петербург: не переносить событие на московские точки.

## Зафиксированный результат

Настоящий `gemini-3.1-flash-lite` обработал четыре опубликованные новости через ту же долговечную очередь, что использует фон приложения. В БД сохранены три рекомендации: «Приостановка работы кофейни» для «Офисов» по посту 23; «Риск срыва доставки» для «Парка» по посту 25; «Подготовка к увеличению потока посетителей» для «Парка» по посту 22. Пост 24 получил `irrelevant`; «Вокзал» не включён в рекомендации. Тексты ответов получены от Gemini, не из этой инструкции или fixture.

Повторный запуск обработки выбранных четырёх источников: `processed:0`, внешних вызовов 0, три карточки сохранены. Повторный setup: `created:0`, `updated:0`, `unchanged:3`, профиль не изменён. Проверен настоящий вход через форму, Enter для отправки и клавиатурный переход в профиль; после reload все три карточки остаются. Главная проверена на 320/768/1440 px, профиль на 320/1440, новость об отключении воды — с действительной ссылкой на источник. Горизонтального скролла и ошибок страницы нет. Снимки хранятся локально в `.local/gemini-screens/`.

Это учебный показ на **16 ноября 2026 года**, а не реальные городские предупреждения. После окончания указанного периода карточки закономерно перестанут быть активными; для другого дня нужно обновить публикации и дождаться нового анализа. Остальные сообщения канала обрабатываются фоном независимо от четырёх проверенных примеров.
